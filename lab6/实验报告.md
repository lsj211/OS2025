## Lab6 实验报告

### 练习二
#### 1. 与 Lab5 的差异分析
- 对比调度入口 `schedule`：Lab5 的实现直接在全局进程链表上线性寻找下一个可运行进程，缺少时间片概念，见 [lab5/kern/schedule/sched.c#L26-L58](lab5/kern/schedule/sched.c#L26-L58)。Lab6 则引入调度类与运行队列抽象，在 [lab6/kern/schedule/sched.c#L17-L113](lab6/kern/schedule/sched.c#L17-L113) 中通过 `sched_class` 回调完成入队/出队/取下一个进程，同时在时钟中断里调用 `sched_class_proc_tick`。如果不做这一改动，时间片轮转等策略无法插拔，时钟无法触发重新调度，进程会长期占用 CPU，无法满足 RR 的公平性需求。

#### 2.RR 各函数实现思路
- `RR_init`（[lab6/kern/schedule/default_sched.c#L18-L24](lab6/kern/schedule/default_sched.c#L18-L24)）：初始化运行队列头结点为空双向链表，清零 `proc_num` 并将 `lab6_run_pool` 置空，为后续入队做好基础状态。
- `RR_enqueue`（[lab6/kern/schedule/default_sched.c#L38-L51](lab6/kern/schedule/default_sched.c#L38-L51)）：先断言当前进程未在队列中，若时间片为 0 或超出上限则重置为 `max_time_slice`，再设置所属队列指针，用 `list_add_before` 把 `run_link` 插到队尾，并递增队列计数。
- `RR_dequeue`（[lab6/kern/schedule/default_sched.c#L60-L68](lab6/kern/schedule/default_sched.c#L60-L68)）：确保节点在队列中后使用 `list_del_init` 脱链并重新初始化节点，最后递减队列进程数，防止计数漂移。
- `RR_pick_next`（[lab6/kern/schedule/default_sched.c#L78-L88](lab6/kern/schedule/default_sched.c#L78-L88)）：从队头 `run_list.next` 获取下一个运行的节点，若队列为空返回 `NULL`，利用 `le2proc` 将链表节点转换为进程指针。
- `RR_proc_tick`（[lab6/kern/schedule/default_sched.c#L98-L109](lab6/kern/schedule/default_sched.c#L98-L109)）：每个时钟滴答将当前进程剩余时间片递减，为零时设置 `need_resched` 触发调度。时间片不会减为负值，避免出现无法重新分配的情况。

#### 4.RR 调度分析
- 优点：实现简单、无饥饿，适合交互场景；缺点是频繁切换带来的开销和对长任务的吞吐影响。
- 时间片大小：时间片过小会增加上下文切换，过大则降低响应度；可根据负载特征调整 `MAX_TIME_SLICE`，例如 I/O 密集型场景可减小以提升响应，CPU 密集型可适当放大减少切换。
- `RR_proc_tick` 设置 `need_resched` 的原因：在中断上下文无法直接切换，需要标记让返回后调用 `schedule`，避免在硬件栈帧尚未收尾时进行上下文切换。

#### 5.拓展思考
- 优先级 RR：可为每个优先级维护独立队列或在单队列中按优先级插入，`RR_enqueue` 按优先级选择插入位置或队列，`RR_pick_next` 优先取最高优先级的队头，时间片可与优先级成比例；`RR_proc_tick` 在时间片耗尽时降级或重新入队保持优先级顺序。
- 多核调度：当前实现仅有单个全局运行队列，不支持多核负载均衡。要支持 SMP，应为每个 CPU 维护本地 run queue，使用自旋锁保护，定期触发 load balance 将任务在核间迁移，并在 `sched_class` 中增加跨核迁移与 steal 接口以减少锁争用。
